## Execution and evidence rules

- Each test result must be updated with exact deployed SHA/image digest, staging/production target, named authorized role, actual provider/device vs mock, browser/OS version, expected and observed HTTP/UI/network/business state, pass/fail status and an access-controlled evidence link.
- Mocked unit tests, read-only DNS, READY Vercel deployment, hosted CI source gate, offline agent output, iOS simulator and physical paid customer all have different evidence levels.
- Negative authorization cases should use isolated synthetic tenants/test accounts with no privileged production data changes. Run duplicate payment callbacks only in approved sandbox and ensure exactly one entitlement.
- Full production user flows require verified backend database migrations, MFA policy, owned resources and recovery. Never substitute a dashboard screenshot for a transaction receipt or accepted API result.
- No physical router modification, commercial customer charging, store submission, drone flight or robot actuation is authorized by adding a row to this matrix.
